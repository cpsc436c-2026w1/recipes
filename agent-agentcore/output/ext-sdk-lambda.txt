## Fixes
1. toollog.py: run_sql rejects a SELECT that reads no table trips (constants, a CTE of constants, a CTE named
   trips); tests: test_the_tool_rejects_a_select_that_does_not_read_trips, test_a_number_the_model_put_in_a_query_
   of_constants_is_not_shown (both SDKs), scenarios R111 "The model writes its own arithmetic as a query", R120
   "A SELECT that does not read trips" and "A computed number read from trips in subqueries".
2. trip_contracts.py SYSTEM_PROMPT (two revisions): half-open time windows and midnight as an end, parentheses
   around OR, computed numbers in one SELECT over trips, fare is the base fare (DS01 keeps tips, tolls and taxes in
   their own columns, which the table leaves out), another day and missing columns answered null without a query.
   Test: the @live @eval scenario (below).
3. features/environment.py: @live scenarios ran on .env.example's offline settings (PREFIX=test, made-up AWS keys,
   no token parameter) and the first one ended behave with "Set KB_MCP_TOKEN_PARAM"; with LIVE=1 they now run on
   the shell's settings. Test: test_a_live_scenario_runs_on_the_shell_settings_and_an_offline_one_on_the_example.
4. Model tokens per question in the function's log line (tokens_in, tokens_out; not in the answer) and
   trip_eval.py --out / its cost line: the cost below is from these counts.
The rejection in fix 1 was not hit again in the live runs after it (every query then read trips): its evidence is
the tests that fail without it. Not fixed: compare-161-230, where the model computes the difference itself and the
value check withholds it (fixed afterwards: fix 5 below).
