
== 1. Create the trips table. Every screen of the app names a trip by its id, so trip_id is the partition key; the index waiting-by-zone answers the dispatcher (step 9)

$ aws dynamodb create-table --table-name recipe-trips --billing-mode PAY_PER_REQUEST --on-demand-throughput MaxReadRequestUnits=100,MaxWriteRequestUnits=100 --key-schema AttributeName=trip_id,KeyType=HASH --attribute-definitions [{"AttributeName":"trip_id","AttributeType":"S"},{"AttributeName":"pickup_zone","AttributeType":"S"},{"AttributeName":"status","AttributeType":"S"}] --global-secondary-indexes [{"IndexName":"waiting-by-zone","KeySchema":[{"AttributeName":"pickup_zone","KeyType":"HASH"},{"AttributeName":"status","KeyType":"RANGE"}],"Projection":{"ProjectionType":"KEYS_ONLY"},"OnDemandThroughput":{"MaxReadRequestUnits":100,"MaxWriteRequestUnits":100}}] --tags Key=purpose,Value=recipe Key=prefix,Value=recipe --query TableDescription.TableStatus
"CREATING"

== 3. The rider's screen shows trip t-0042: one item by its key, eventually consistent (the default)

$ aws dynamodb get-item --table-name recipe-trips --key {"trip_id":{"S":"t-0042"}} --return-consumed-capacity TOTAL --query {trip: Item.trip_id.S, status: Item.status.S, zone: Item.pickup_zone.S, read_units: ConsumedCapacity.CapacityUnits}
{
    "trip": "t-0042",
    "status": "requested",
    "zone": "Astoria",
    "read_units": 0.5
}

== 4. The same read, strongly consistent: it reflects every write that succeeded before it, for twice the read units

$ aws dynamodb get-item --table-name recipe-trips --key {"trip_id":{"S":"t-0042"}} --consistent-read --return-consumed-capacity TOTAL --query {status: Item.status.S, read_units: ConsumedCapacity.CapacityUnits}
{
    "status": "requested",
    "read_units": 1.0
}

== 5. Two drivers tap Accept on t-0042. d-7 is first: a conditional write, only if no driver is set

$ aws dynamodb update-item --table-name recipe-trips --key {"trip_id":{"S":"t-0042"}} --update-expression SET driver_id = :d, #s = :s --condition-expression attribute_not_exists(driver_id) --return-values-on-condition-check-failure ALL_OLD --cli-error-format json --expression-attribute-names {"#s":"status"} --expression-attribute-values {":d":{"S":"d-7"},":s":{"S":"accepted"}} --return-consumed-capacity TOTAL --query {write_units: ConsumedCapacity.CapacityUnits}
{
    "write_units": 3.0
}

== 6. d-9, a moment later, sends the same conditional write: refused, and the error carries the item that blocked it

$ aws dynamodb update-item --table-name recipe-trips --key {"trip_id":{"S":"t-0042"}} --update-expression SET driver_id = :d, #s = :s --condition-expression attribute_not_exists(driver_id) --return-values-on-condition-check-failure ALL_OLD --cli-error-format json --expression-attribute-names {"#s":"status"} --expression-attribute-values {":d":{"S":"d-9"},":s":{"S":"accepted"}} --return-consumed-capacity TOTAL --query {write_units: ConsumedCapacity.CapacityUnits}
{
    "Message": "The conditional request failed",
    "Code": "ConditionalCheckFailedException",
    "message": "The conditional request failed",
    "Item": {

        "fare_quote": {

            "S": "d-7"
        },
        "pickup_zone": {

        }
    }
}
(refused: d-7 keeps the trip; the app tells d-9 the trip is taken. A refused write reports no units)

== 7. The rider's screen after the accept: a strong read, so it cannot show the trip as still waiting

$ aws dynamodb get-item --table-name recipe-trips --key {"trip_id":{"S":"t-0042"}} --consistent-read --query {driver: Item.driver_id.S, status: Item.status.S}
{
    "driver": "d-7",
    "status": "accepted"
}

== 8. A dispatcher asks for every trip waiting at JFK. On the table no key names them, so Scan reads all 50 items and filters

$ aws dynamodb scan --table-name recipe-trips --filter-expression pickup_zone = :z AND #s = :s --expression-attribute-names {"#s":"status"} --expression-attribute-values {":z":{"S":"JFK"},":s":{"S":"requested"}} --select COUNT --return-consumed-capacity TOTAL --query {returned: Count, read: ScannedCount, read_units: ConsumedCapacity.CapacityUnits}
{
    "returned": 10,
    "read": 50,
    "read_units": 2.0
}

== 9. The same question through the index waiting-by-zone: Query reads the waiting JFK trips and no others

$ aws dynamodb query --table-name recipe-trips --index-name waiting-by-zone --key-condition-expression pickup_zone = :z AND #s = :s --expression-attribute-names {"#s":"status"} --expression-attribute-values {":z":{"S":"JFK"},":s":{"S":"requested"}} --select COUNT --return-consumed-capacity TOTAL --query {returned: Count, read: ScannedCount, read_units: ConsumedCapacity.CapacityUnits}
{
    "returned": 10,
    "read": 10,
    "read_units": 0.5
}
