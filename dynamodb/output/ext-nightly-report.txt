
== 1. The report the slow way: Scan reads every trip through the table, and every item read is billed

$ aws dynamodb scan --table-name recipe-trips --projection-expression 'pickup_zone, fare_quote' --return-consumed-capacity TOTAL --query '{items_read: ScannedCount, read_units: ConsumedCapacity.CapacityUnits}'
{
    "items_read": 52,
    "read_units": 2.0
}

== 2. Exports need point-in-time recovery (PITR) switched on for the table

$ aws dynamodb update-continuous-backups --table-name recipe-trips --point-in-time-recovery-specification PointInTimeRecoveryEnabled=true --query ContinuousBackupsDescription.PointInTimeRecoveryDescription.PointInTimeRecoveryStatus
"ENABLED"

== 3. Start a full export to S3. It does not use the table's read units

== 6. A table in Athena over the data files. Each line is {"Item": {attribute: {type: value}}}

$ athena: CREATE DATABASE IF NOT EXISTS recipe_lake
{
    "state": "SUCCEEDED",
    "reason": null,
    "scanned_bytes": 0
}

$ athena: DROP TABLE IF EXISTS recipe_lake.trips_export
{
    "state": "SUCCEEDED",
    "reason": null,
    "scanned_bytes": 0
}

$ athena: CREATE EXTERNAL TABLE recipe_lake.trips_export (
  Item struct<trip_id:struct<S:string>, status:struct<S:string>, pickup_zone:struct<S:string>,
              fare_quote:struct<N:string>, driver_id:struct<S:string>>)
ROW FORMAT SERDE 'org.openx.data.jsonserde.JsonSerDe'
LOCATION 's3://my-bucket-111122223333/recipe/exports/AWSDynamoDB/01792642793032-7ad3ea66/data/'
{
    "state": "SUCCEEDED",

    "scanned_bytes": 0
